پرسش‌های نظری Git

۱. پوشه .git چیست؟

پوشه .git هسته repository محلی Git است و اطلاعات مربوط به objectها، branchها، commitها، تنظیمات، logها و staging area را نگهداری می‌کند.

  • HEAD: مرجع فعلی
  • objects: objectهای Git
  • refs: branchها و tagها
  • index: staging area
  • config: تنظیمات repository
  • logs: سوابق referenceها

Atomic Commit و Atomic Pull Request

atomic یعنی تغییر از نظر منطقی یک واحد کامل و قابل فهم باشد. در یک atomic commit نباید چند تغییر مستقل و بی‌ارتباط کنار هم قرار گیرند.

یک atomic pull request نیز باید یک هدف روشن داشته باشد؛ برای مثال «افزودن بخش پاسخ پرسش‌های Git» بهتر از PRای است که هم‌زمان CSS، workflow و محتوای نامرتبط را تغییر دهد.

fetch، pull و merge

git fetch تغییرات remote را دریافت می‌کند ولی branch فعلی را مستقیماً ادغام نمی‌کند.

git pull معمولاً fetch و سپس merge یا rebase است.

git merge دو تاریخچه را ادغام می‌کند.

rebase و cherry-pick

git rebase commitهای یک branch را روی یک پایه جدید بازنویسی می‌کند.

git cherry-pick یک commit مشخص را روی branch فعلی اعمال می‌کند.

reset و revert

git reset می‌تواند pointer شاخه و وضعیت index/worktree را تغییر دهد.

git revert با ایجاد یک commit معکوس، اثر commit قبلی را خنثی می‌کند و برای branchهای اشتراکی معمولاً انتخاب امن‌تری است.

restore، switch و checkout

git restore برای بازیابی فایل‌ها و وضعیت index/worktree کاربرد دارد.

git switch برای جابه‌جایی بین branchها طراحی شده است.

git checkout دستور قدیمی‌تر و چندمنظوره‌ای است که هم برای branch و هم برای restore فایل استفاده می‌شد.

Stage و Stash

staging area یا index ناحیه‌ای بین working tree و commit است. فایل را با git add وارد این ناحیه می‌کنیم.

git stash تغییرات موقت working tree و index را ذخیره می‌کند تا بتوانیم موقتاً branch یا context کاری را عوض کنیم.

Snapshot و Commit

Git به‌جای ذخیره صرفاً یک diff خط‌به‌خط، نمایی از وضعیت فایل‌ها را به‌صورت snapshot مدل می‌کند.

یک commit به یک snapshot مشخص اشاره می‌کند و همچنین parent، author، committer، message و metadata مرتبط را دارد.

Local Repository و Remote Repository

local repository روی سیستم توسعه‌دهنده قرار دارد و شامل working tree، index و history محلی است.

remote repository نسخه‌ای اشتراکی از repository روی سرویس‌هایی مانند GitHub است که برای collaboration، backup و integration استفاده می‌شود.
