Conflict Resolution

دو سناریوی واقعی رفع تعارض

Conflict 01

تعارض هنگام rebase

دو توسعه‌دهنده یک بخش مشترک از index.html را در یک branch تغییر دادند. با git pull --rebase تعارض ایجاد شد. 

git status
grep -n -E '<<<<<<<|=======|>>>>>>>' index.html
git add index.html
git rebase --continue
Conflict 02

تعارض در Pull Request

branch مربوط به deployment پس از تغییر develop دیگر قابل merge مستقیم نبود. وضعیت جدید branch دریافت و conflict در README.md به‌صورت دستی حل شد. 

git fetch origin
git merge origin/develop
git status
git add README.md
git commit -m "fix: resolve deployment documentation conflict"

۰۷

پرسش‌های نظری

پاسخ ۷ پرسش اصلی Git

۱. پوشه‌ی .git چیست؟

پوشه‌ی .git هسته‌ی repository محلی Git است. این پوشه با git init ایجاد می‌شود و metadata، objectها، referenceها، تنظیمات، logها و index را نگه می‌دارد. فایل HEAD مرجع فعلی را مشخص می‌کند، پوشه‌ی objects آبجکت‌هایی مانند commit، tree و blob را نگه می‌دارد، refs برای branchها و tagها استفاده می‌شود و index همان staging area است.

۲. Atomic در commit و Pull Request یعنی چه؟

یک تغییر atomic یک واحد منطقی و کامل است. یک atomic commit باید یک هدف روشن داشته باشد و ترجیحاً فقط یک تغییر مستقل را ثبت کند. Pull Request نیز بهتر است یک هدف مشخص داشته باشد تا review، تست، rollback و نگهداری آن ساده باشد.

۳. تفاوت fetch، pull، merge، rebase و cherry-pick چیست؟

git fetch اطلاعات remote را دریافت می‌کند ولی branch فعلی را ادغام نمی‌کند. git pull معمولاً fetch و سپس merge یا rebase است. git merge دو تاریخچه را ادغام می‌کند. git rebase commitها را روی پایه‌ای جدید بازنویسی می‌کند. git cherry-pick یک commit مشخص را انتخاب و روی branch فعلی اعمال می‌کند.

۴. تفاوت reset، revert، restore، switch و checkout چیست؟

reset می‌تواند reference و در حالت‌های مختلف index و working tree را جابه‌جا کند. revert یک commit جدید برای خنثی‌کردن اثر commit قبلی می‌سازد. restore برای بازیابی فایل‌ها و index طراحی شده است. switch برای جابه‌جایی branchهاست. checkout دستور قدیمی‌تر و چندمنظوره‌ای است که هم branch و هم restore فایل‌ها را پوشش می‌داد.

۵. Stage یا Index چیست و stash چه کاری می‌کند؟

staging area یا index ناحیه‌ای بین working tree و repository است. با git add فایل‌ها را برای commit بعدی انتخاب می‌کنیم. git stash تغییرات محلی را موقتاً کنار می‌گذارد تا working tree تمیز شود و بتوان بدون commit دائمی branch یا context را عوض کرد.

۶. Snapshot چیست و چه ارتباطی با commit دارد؟

snapshot نمایی از وضعیت پروژه در یک نقطه از تاریخچه است. commit به یک snapshot مشخص اشاره می‌کند و همراه آن parent، author، committer، زمان و پیام commit نیز ثبت می‌شود. Git برای ذخیره‌ی این ساختار از object model خود استفاده می‌کند و داده‌های تکراری را تا حد امکان به شکل مشترک نگه می‌دارد.

۷. تفاوت local repository و remote repository چیست؟

local repository روی سیستم توسعه‌دهنده قرار دارد و working tree، index و history محلی را در بر می‌گیرد. remote repository روی سرویسی مانند GitHub قرار دارد و برای همکاری، code review، backup و CI/CD استفاده می‌شود. این دو repository مستقل‌اند و با فرمان‌هایی مانند push، fetch و pull با هم همگام می‌شوند.
